from agntspark import Client, DeployConfig

with Client() as client:
    agent = client.agents.create(
        "support",
        model="gpt-4o",
        api_key=OPENAI_API_KEY,
        deploy=DeployConfig(
            image="agntspark/template-customer-support",
        ),
    )
    # Private by default: the first key is returned once.
    key = agent.access_key

    reply = client.agents.invoke(
        agent, "I was charged twice this month.",
        access_key=key,
    )
    print(reply.output)

How it works

From a container image to a working endpoint in three steps.

You don't run a cluster, write ingress rules or renew certificates. You choose what the agent is; the platform keeps it reachable and fenced in.

Pick what to run

An official template, a blank agent with your own system prompt, or any public container image that serves /health and /invoke.

Deploy it

From the console, the API, the Python SDK or the CLI. Choose the model, add your provider key, and set replicas, CPU and memory.

Call it with its key

The agent answers at its own URL. Give each app its own access key, revoke keys independently, and cap how fast any one caller can go.

Features

The parts of running an agent that aren't the agent.

Everything below is in the platform today.

A URL for every agent

Each agent answers at https://<name>.run.agntspark.com, with its certificate issued and renewed automatically.

Access keys

New agents are private. Create a key per app, see previews of each, and revoke one without touching the rest.

Rate limits

A per-caller limit you choose, checked before the key, plus a per-agent ceiling from your plan — so a leaked URL can't run up your bill.

Bring your own model key

OpenAI, Anthropic or Google. Stored encrypted, masked everywhere, and only decrypted when your agent's container starts.

Replicas and auto-scaling

Run several replicas, scale by hand or let the platform adjust between your minimum and maximum — never past your plan.

Logs, metrics and usage

Container logs, live CPU and memory, and metered replica-, vCPU- and memory-hours plus request counts, by the hour.

Isolation & security

Fenced in by default.

What we do so one customer's agent can't reach another's — and what we'd rather tell you than have you discover.

Plainly: agents from different customers share a host kernel, as containers do. That's one reason the alpha is invite-only; stronger sandboxing is on our roadmap. The platform currently runs on a single host, with nightly database backups.
  • No agent-to-agent traffic. Firewall rules drop traffic between agent containers; agents reach each other only through their public URLs.
  • Separate networks. Agents can't reach the platform's database, cache or API internals, or the cloud metadata service.
  • Least privilege. Containers drop Linux capabilities, can't gain privileges, and have CPU, memory and process limits.
  • Secrets encrypted at rest. Model keys and secret environment variables are encrypted and shown masked.
  • Keys stored as hashes. API keys and access keys are shown once, then kept only as SHA-256 hashes.
  • Roles and quotas. Viewer, developer and admin roles are enforced, and plan quotas are checked before anything starts.

FAQ

Questions people ask first.

How do I get access?

The alpha is invite-only. Email admin@agntspark.com with what you want to build, and we'll send an invite code. Sign up at agntapi.agntspark.com with that code.

Do you charge for model usage?

No. You bring your own OpenAI, Anthropic or Google key, and your provider bills you directly. AgntSpark charges only for hosting, per the plans above.

What can I deploy?

An official template, a blank agent with your own prompt on the platform runtime, or any public container image that listens on its port and serves GET /health and POST /invoke. Building from source isn't supported yet — push an image first.

Can anyone call my agent if they find its URL?

Not by default. New agents are private: requests without one of the agent's access keys are refused at the edge before they reach your container. You can make an agent public, and rate limits apply either way.

Where does it run?

On Google Cloud. The platform currently runs on a single host; there's no multi-region deployment or uptime SLA during the alpha. Database backups run nightly.

What happens if I cancel Pro?

You keep Pro until the end of the billing period, then return to the free plan's limits. Running agents keep running; you just can't add resources past the free limits.
